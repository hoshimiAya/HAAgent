# 提交规范（AI 主导）

本文件主要供 AI 读取，用于分析 git diff 并生成规范 commit message。
人类读者只需了解结构，不必记规则。

---

## 0. 调用方式

用户提供：
- `git diff --staged` 或 `git diff HEAD` 的输出
- 可选：本次变更的背景说明

AI 输出：
- 若变更应拆分为多个 commit，先给出拆分建议（见 §5）
- 否则直接给出 commit message（见 §1）

---

## 1. 输出格式（硬约束）

    <type>: <简述>

    [可选正文]

- 首行 ≤ 50 字符，无句号，动词或名词短语开头
- 第二行为空行（若有正文）
- 正文用中文，说"为什么"，不复述"做了什么"
- 无正文时只有一行

---

## 2. type 决策表（按 diff 内容判断）

| diff 特征 | type |
|-----------|------|
| 新增函数 / 类 / 路由 / 接口 | `feat` |
| 修复可复现的错误行为 | `fix` |
| 改结构、不改外部行为（重命名、抽函数、换实现） | `refactor` |
| 仅改注释、文档、README、docs/ | `docs` |
| 构建脚本、依赖、配置文件、CI | `chore` |
| 仅改空白、缩进、格式化 | `style` |
| 新增/修改测试 | `test` |
| 性能优化，且行为不变 | `perf` |

**多特征时优先级**：`fix` > `feat` > `refactor` > `perf` > `test` > `docs` > `chore` > `style`

若 diff 同时含多个不相关特征 → 触发 §5 拆分。

---

## 3. 标题生成规则

提取：
1. diff 中**新增/删除最多的符号**所在模块
2. 该模块下**最核心的行为变化**

措辞模板：
- 新增：`添加 X` / `实现 X` / `接入 X`
- 删除：`移除 X` / `删除 X`
- 修改：`X 改为 Y` / `调整 X`
- 修复：`修复 X` / `解决 X 导致的 Y`

**禁用词**（无信息量）：
`更新` `修改` `提交` `调整一下` `小改` `fix` `bug fix` `WIP`

**推荐长度**：15–40 字符，能把"哪个模块做了什么"说清。

---

## 4. 正文生成规则

**写正文的条件**（满足任一）：
- 修复的 bug 根因不在表面（需解释"为什么这么改"）
- 涉及破坏性变更（API、配置、数据格式）
- 有一次取舍（选了方案 A，放弃了 B）
- 引入新的外部依赖或约束

**不写正文**：新增独立文件、重命名、单纯补文档、加个 handler。

正文格式：
- 中文，短句，无标点堆砌
- 可分段，每段 ≤ 3 行
- 不要列表符号，直接自然段

---

## 5. 拆分规则

一个 commit 只做一件事。判断标准：

**必须拆分**：
- 同时有 `feat` 和 `fix`
- 同时改 src/ 和 docs/（除非文档是代码的必附说明）
- 同时改多个独立模块（如 `llm/` 和 `routing/`）

**不必拆分**：
- 一个功能涉及多个文件
- 一个 bug 的修复改动多处
- 重构 A 时顺手调整了 A 的调用方

拆分建议输出格式：

    建议拆为 2 个 commit：
    1. feat: 添加 HttpClient 同步 POST 封装
    2. refactor: LLMClient 改用 HttpClient

---

## 6. 本项目术语表

提交时优先使用下列模块名（与目录名一致）：

| 目录 / 文件 | 提交中的称呼 |
|-------------|--------------|
| `src/core/server.*` | Server |
| `src/core/session.*` | Session |
| `src/routing/router.*` | Router |
| `src/llm/chat_engine.*` | ChatEngine |
| `src/llm/chat_session_manager.*` | ChatSessionManager |
| `src/llm/llm_client.*` | LLMClient |
| `src/llm/chat_context.hpp` | ChatContext |
| `src/main.cpp` | 入口 / main |

外部库：
- Beast（不要写 `boost::beast` 全名，除非在正文）
- Asio（同理）
- nlohmann-json（或写 `nlohmann`）

## 7. 示例（diff → commit）

### 示例 1：新增文件

**diff**：新增 `src/llm/http_client.hpp` 和 `src/llm/http_client.cpp`，实现 `HttpClient::post()`。

**输出**：

    feat: 添加 HttpClient 同步 POST 封装

### 示例 2：修 bug，根因不直观

**diff**：`session.cpp` 中 `path` 的赋值从 if 内部移到 if 之前。

**输出**：

    fix: Session 空 target 导致 404

    handle_request 里 path 只在 target 含 ? 时赋值，
    导致所有不带 query 的请求全部走 404。
    改成先 path = target，再按 ? 拆 query。

### 示例 3：重构 + 依赖变更，需拆分

**diff**：
- `vcpkg.json` 增加 `nlohmann-json`
- `llm_client.cpp` 改用 nlohmann-json 解析响应
- `main.cpp` 删除注释掉的示例代码

**输出**：

    建议拆为 3 个 commit：
    1. chore: vcpkg.json 添加 nlohmann-json 依赖
    2. refactor: LLMClient 使用 nlohmann-json 解析响应
    3. chore: 删除 main.cpp 中无用的示例注释

### 示例 4：文档更新

**diff**：`docs/架构.md` 中移除 HttpParser 类。

**输出**：

    docs: 架构图移除已删除的 HttpParser

### 示例 5：多个模块混合，需拆分

**diff**：修改 `chat_engine.cpp`（接入 LLMClient）和 `session.cpp`（改超时）。

**输出**：

    建议拆为 2 个 commit：
    1. refactor: ChatEngine::process 接入 LLMClient
    2. fix: Session 读写超时调整为 30 秒

---

## 8. 反例

| 反例 | 问题 |
|------|------|
| `更新` | 没信息 |
| `fix bug` | 没信息，且未指定模块 |
| `feat: 添加功能` | 什么功能？ |
| `修改 session.cpp 里的几行代码` | 复述 diff，没有意图 |
| `feat: 添加 HttpClient 并修复 Session 超时并更新文档` | 三件事塞一个 commit |

## 9. 让 AI 生成 commit 的操作步骤

**前提**：你手头有一批已 `git add` 过、还没 `commit` 的改动。

**步骤**：

1. 终端跑，打印暂存区内容：

       git diff HEAD > diff.txt

2. 复制 diff.txt 输出。

3. 到 AI 对话里，粘这段话 + 第 2 步复制的内容：

   > 分析以下 git diff，按 `docs/提交规范.md` 生成 commit message。
   > 若需要拆分，先给拆分方案。
   >
   > ```
   > （粘贴第 2 步复制的内容）
   > ```

4. AI 返回 commit message（或拆分建议）。

5. 提交：

       git commit -m "<AI 给的 message>"

**还没 git add 怎么办**：

    git add -A          # 或者 git add <具体文件>

再回到第 1 步。

**想确认暂存区里有什么**：

    git status
